# os-basic

## 컴퓨터 구조
![os-structure](/images/os-structure.png)

```text
[ Hardware ]
 ├─ CPU
 ├─ Memory (RAM)
 ├─ Storage (Disk)
 └─ I/O Devices
        ↑
[ Operating System (Kernel) ]
        ↑
[ User Space Programs ]
        ↑
[ User (Human) ]
```
- 하드웨어는 직접 만질 수 없다
- CPU, Memory, Disk 는 아무 프로그램이나 직접 접근하면 시스템에 문제가 생길 수 있다
- 그래서 중간 관리자 역할이 필요하고, 그것이 OS(Operating System)이다

### 그런데, 왜 “아무 프로그램이나 CPU/메모리/디스크를 직접 만지면” 시스템에 문제가 생길 수 있는걸까?
- 동시성 문제
    - 여러 프로그램이 동시에 “같은 자원”을 쓰면 충돌함
        - 예: 두 프로그램이 같은 파일의 같은 위치를 동시에 쓰면 데이터가 섞임(race condition)
- 보호(Protection) 문제
    - 악의적/버그 있는 프로그램이
        - 다른 프로그램 메모리를 읽거나
        - 시스템 설정을 바꾸거나
        - 디스크를 덮어쓰면
    - 시스템 전체가 깨짐
- 복잡도(Complexity) 문제
    - 디스크/NIC/USB 같은 장치는 동작이 너무 복잡하고 제조사마다 다름
    - 모든 앱이 장치 제어 코드를 직접 갖고 있으면 개발도 불가능, 안정성도 불가능
> 그래서 OS는 단순히 “중간 관리자”가 아니라,<br>
(1) 공유를 관리하고 (2) 보호를 강제하고 (3) 하드웨어 복잡도를 숨기는 계층인 것

## OS가 제공하는 3대 가치
### 추상화(Abstraction)
- 하드웨어를 "쓰기 쉬운 API/개념”으로 바꿔서 제공
    - CPU → 프로세스/스레드라는 추상화로 “내 프로그램이 혼자 CPU 쓰는 것처럼”
	- 메모리 → **가상 메모리(Virtual Memory)** 로 “내 프로그램만의 주소 공간이 있는 것처럼”
	- 디스크 → **파일/디렉터리(File system)** 로 “블록 장치”를 파일 구조로
	- 네트워크 → **소켓(Socket)** 으로 TCP/IP를 API로
> 개발자는 하드웨어 모델을 몰라도 프로그래밍 가능

### 보호(Protection) / 격리(Isolation)
- 프로그램이 서로를 망치지 못하게 강제로 막음
	- 프로세스마다 주소 공간 분리
	   - A 프로그램이 B 프로그램 메모리를 마음대로 못 읽음
	- 권한(사용자/그룹/권한 비트, ACL)
        - 어떤 파일을 읽고/쓰고/실행할지 통제
	- 커널이 “안전한 경계”를 제공
	   - 위험한 작업은 OS를 통해서만 하게 만들고 검사함

### 자원관리(Resource Management)
| 자원 | OS 역할 |
|---|---|
| CPU | 어떤 프로세스가 언제 얼마나 실행될지 스케줄링 |
|Memory | 각 프로세스에 메모리 할당/회수 + 부족할 때 스왑/페이지 교체 |
| Disk | 파일 시스템으로 안전하게 접근 + 디스크 I/O 스케줄링 |
| Network | 소켓, 포트, 버퍼/큐 관리 |
| Device | 키보드, 디스크, NIC 제어 |

> OS 없으면 프로그램은 실행 자체가 불가능
